需求发现与验证

不做拍脑袋的功能

问卷调研 + 深度访谈 + KANO模型分类 → 区分基本型/期望型/兴奋型需求 → 确定优先级。两个项目都遵循了这套流程。

原型设计与文档

让想法可被看见和讨论

Figma 高保真可交互原型 + 完整PRD（功能详述/交互规则/异常流程/埋点方案/验收标准）→ 确保设计意图能被开发团队准确理解。

AI 协同开发

需求精度决定AI产出质量

用 Cursor 辅助全栈开发的经验让我深刻理解了「需求描述精确度 → 开发产出质量」的因果关系——这本质上是PM与工程师沟通的训练。

数据驱动迭代

用数字验证假设，而非感觉

定义核心指标 → 埋点追踪 → 分析转化漏斗 → 提出假设 → 上线验证 → 复盘。搭子成行匹配率40%→65%就是这个闭环的结果。
